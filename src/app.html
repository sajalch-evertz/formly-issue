Issue 1: a replaced [model] reference loses the selected branch's defaults

This page renders the form with an empty model, then replaces the [model] reference with a fresh empty record one tick later: what a host does when it renders before its data arrives, and what any ControlValueAccessor wrapper does in writeValue. Every default should be re-applied to the new record. name, enabled and retries are; the selected branch's method and timeoutMs are not.

Issue 2: switching branch changes the model but leaves the form pristine

Switch the branch selector between HTTP and File. The model changes, and form.dirty stays false, because the selector Formly builds for the branches has no key and so is never attached to the form. Switching also restores the branch defaults, which shows the code that applies them works and simply never runs on a rebuild.

Issue 3: the branch selector carries no label and no supported way to give it one

The oneOf node's "title": "Output" never reaches the selector, which renders with whatever fallback text the field type hardcodes (Select, here). The selector has no key and is the one field toFieldConfig's map callback is never called for, so there is no supported way to label, translate or otherwise configure the choice the user is making.
