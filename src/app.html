ngx-formly 7.1.0: a hide expression loses a field's default

Two issues. The first is not about schema composition: any field whose self or ancestor carries a hide expression loses its schema default when the [model] reference is replaced, even while the field is visible. Every oneOf form is affected without opting in, because resolveMultiSchema() puts a hide expression on every branch. URL and Path below additionally carry one of their own, "hide": "!formState.isAdmin" with isAdmin: true, so they are visible the whole time. Name has none and is the control.

Nothing here is customised beyond the field types the JSON Schema guide tells you to register, and Bootstrap is a stylesheet only: @ngx-formly/bootstrap is not installed.

Issue 1: a replaced [model] reference loses the branch's defaults

This page renders the form with an empty model, then replaces the [model] reference with a fresh empty record one tick later: what a host does when it renders before its data arrives, and what any ControlValueAccessor wrapper does in writeValue. Every default should be re-applied to the new record. name is; nothing inside the branch is, the gated URL included.

Issue 2: switching branch changes the model but leaves the form pristine

Switch the branch selector between HTTP and File. The model changes, and form.dirty stays false, because the selector Formly builds for the branches has no key and so is never attached to the form. Switching also restores the branch defaults, which shows the code that applies them works and simply never runs on a rebuild.

To reach Discard, switch the branch to bring the defaults back, then edit a field. Discard writes the loaded record back in and marks the form pristine, as a ControlValueAccessor host does. That write replaces the [model] reference, so the branch defaults empty again: issue 1 fires on every discard, not just at load.
